# Implementation notes

The application is organized as a MERN project: React owns the author and operations interfaces; Express exposes the REST contract and role checks; Mongoose models author catalogs, tickets, messages, and private notes in MongoDB. The Express app is shared by a local server bootstrap and a Netlify Function adapter, keeping route behavior consistent across local and serverless deployments.

I prioritized the core ticket lifecycle: an author signs in, sees only their own books and tickets, submits an inquiry, and follows the conversation. Operations staff can search and filter the incoming queue, override classification and priority, assign ownership, add private notes, draft a response from policy context, edit it, and send it. The sample JSON seeds all provided author and book records into MongoDB.

Ticket classification and priority scoring use `gpt-4o-mini` when `OPENAI_API_KEY` is configured. I chose it for the short, structured classification and support drafts because it keeps latency and per-ticket cost low; `OPENAI_MODEL` can be changed without code edits. The prompt requests a constrained JSON category, priority, and confidence; values are validated against the application enums. The deterministic classifier handles missing credentials, timeouts, provider errors, or invalid output, so ticket creation remains available. Operations can override either value, and the source is recorded as AI, rule fallback, or manual override.

AI drafting uses the same model choice for concise responses and sends only the selected ticket, relevant ledger facts, and compact policy context. It does not send other authors or the full ticket database. Prompts use bounded output sizes and timeouts; category-specific grounded templates preserve the manual response workflow when the provider is unavailable. The API key remains server-side in an environment variable.

The prototype uses shared demo credentials and polling to keep setup short. Ticket attachments are persisted in MongoDB with strict type and size limits and owner/admin-only download access; production should move bytes to private object storage and scan them before use. Before production I would add individual account onboarding and password recovery, CSRF/rate controls, durable audit trails for changes and outbound responses, and event-based updates. Docker Compose supports local deployment; Netlify deploys the Vite build and Express Function separately against managed MongoDB, configured with runtime secrets.
